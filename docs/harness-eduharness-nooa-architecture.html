概念基準

先把「基本 Harness」與「本機 Harness」分開

基本／通用 Harness 是 AI Agent 的概念層：位於模型與外部世界之間，負責 context／memory、工具調用、權限、state、執行迴圈、錯誤處理、verification 與 observability。

本機 Harness 則是 eduHarness-/harness/ 的具體實作，包含 Kernel、Registry、Route Plan、Skill resolution、platform preflight、user authority、verify / replan。

重要：「基本 Harness → 本機 Harness」是概念到實作的對照，不表示 repository fork 或版本血統。
01 · 本機 Harness
治理＋執行骨架

把任務拆成可驗證 blocks，以 Route Plan、平台預檢、使用者權限、執行與 verifier 管理生命週期。

→
02 · eduHarness
教育領域化

在 Harness 上加入 Brain、教育 Knowledge、17 個 Skill packages、教案／命題／遊戲／視覺等工作流。

→
03 · eduHarness_Nooa
雲端與雙層治理

把安裝、控制平面、儲存與 canonical distribution 解耦；Registry v3 分成 Official + Local。

Distribution：2026.08.13-registry-v3 · architecture v0.3 · stable

基本 Harness 是什麼？

LLM／模型負責理解、生成與提出候選行動；Harness 則是模型外圍的執行、控制與證據層，決定模型能看到什麼、能使用哪些工具、哪些動作允許執行、狀態如何保存，以及結果怎麼驗證。

本機 Harness：eduHarness repository 裡的具體實作

原始架構把治理規則與執行環境分開，並使用 Kernel、Environment、Skill packages、Registry、Reasoning blocks、Route Plan、Skill resolution、Platform preflight、Runtime adapters 與 State。

自適應任務循環：從理解任務到驗證與重規劃

前段：理解與規劃

任務分類 → 脈絡 → 推理 → Route Plan。

中段：權限與執行

平台預檢 → 使用者裁決 → 派送 → 執行。

後段：整合與修正

結果整合 → 驗證 → 只重規劃受影響路徑。

eduHarness：把 Harness 變成教育工作台

eduHarness 在本機 Harness 上加入 Brain／Knowledge／Templates 與 17 個 Skill packages，涵蓋教案、數位學習、差異化、命題、臆測、文件攝取、推理、Web 教學遊戲、3D、視覺與寫作輸出。

Skill

針對特定教育或產出工作整理好的能力模組，包含使用時機、輸出規則、相依 Skill、工具與驗證方式。

Brain

知識、Skill 與範本先索引、後按需載入；不因建立任務就把全部資料放入 context。

架構重點：Route Plan 決定工作節點與依賴；Skill resolution 決定這些節點需要哪些 Primary／Supporting Skill。Skill 不會偷偷改寫 Route Plan。

Skill 的功能與套件契約

Skill 不只是 prompt；它是可註冊、可驗證、可按需載入的工作能力套件。Registry 記錄 ID、繁中名稱、kind、trigger／anti-trigger、dependencies、capabilities、preferred platforms、verifier policy、required files 與 package hash。

使用者用途 → Skill workflow

Skill dependency 條件

條件用途
always選到父 Skill 就載入。
content-input有文件／內容來源時才載入。
reasoning-needed需要較完整推理時才載入。
verifier-requiredRoute Plan 安排 verifier 時才符合。
high-risktask risk 為 high / critical 時才符合。
user-confirmed必須停在 user-authority，讓使用者決定載入或略過。

範例：PDF 教材 → 數位教案 → 題庫

Node A：文件內容攝取 Skill = document-to-markdown-ingestion ↓ depends_on Node B：數位學習教案 Primary Skill = digital-learning-lesson-plan Supporting dependency = lesson-plan-authoring (always) ↓ depends_on Node C：試題命題 Skill = item-authoring ↓ Final verification

注意：Node A → B → C 是 Route Plan 的工作依賴；「數位學習精進教案 → 教案撰寫」是 Skill dependency。兩者不是同一件事。

實作邊界：Registry 有 triggers / anti-triggers，但目前檢視到的 classify.mjs 主要記錄 profile signals；不能直接宣稱目前 runtime 已完整實作「自然語言 → trigger → 自動挑 Skill」。

eduHarness_Nooa：Cloud v0.3 / Registry v3

目前 active Distribution 為 2026.08.13-registry-v3、Architecture v0.3、channel stable。核心是 Descriptor-first、Provider-separated，以及 Official Registry + Local Registry 的雙層治理。

Official 路徑

Official Registry → pinned GitHub immutable snapshot → canonical Skill path → read full Skill → execute

Local 路徑

Local Registry → artifact://installation/... → Artifact Index → provider stable identity / revision → Storage Provider

權限與路由優先順序

Project governance > Local explicit policy > Official Registry > Skill self-routing

Official Registry 為 pinned GitHub snapshot；Local Registry 為 installation-owned overlay；兩者在 runtime 建立 ephemeral Effective Routing View，不形成第三個持久化 SSOT。

版本注意：README 中仍有 v0.2 / Registry v2 描述；較新的 active Distribution、Project Instructions 與 Official Registry 已推進到 v0.3 / Registry v3。
